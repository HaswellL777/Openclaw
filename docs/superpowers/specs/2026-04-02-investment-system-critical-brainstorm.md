# OpenClaw 投资系统：批判性发散思考

> 日期：2026-04-02
> 输入：handoff-2026-04-02-infra-complete.md（三阶段投资系统规划）
> 方法：多角色批判分析 + 外部研究（学术、监管、市场结构）

---

## 核心张力

这套系统最本质的矛盾是：**你建了一座精密的工厂，但还不知道要生产什么。**

OpenClaw 的基础设施——多 agent 编排、broker 安全链、Docker sandbox、GUI、备份恢复——是一套通用的 agent-as-a-service 控制平面。它的设计哲学是「安全地让 LLM 做有副作用的事」。但三阶段投资规划把它钉死在了一个特定方向上：用 LLM agent 做投资决策。而学术界的共识是，大多数 LLM agent 在严格回测中跑不赢 buy-and-hold（StockBench, ICLR 2026; "Can LLMs Trade?", Apr 2025）。

更深层的张力：这套系统的真正价值在于 orchestration（编排能力）和 safety boundary（安全边界），而不是任何单一 agent 的推理质量。但投资恰恰是「推理质量就是一切」的领域——市场不会因为编排架构优雅就给出超额收益。

## 推进方案

### 方案 A：验证-优先路线（修正版三阶段）

**逻辑闭环**：投资是目标，但承认 LLM 的局限性，定位为「研究助手 + 执行管道」而非「自主交易员」。

**做法**：
- Phase 1 不做 paper trading 模拟引擎。做 **research harness**：agent 负责数据采集、因子计算、回测执行、报告生成，投资决策由人做。task-runner 跑 Python 回测代码（backtrader/zipline），research-coordinator 编排多步研究，auditor 审查回测方法论的 look-ahead bias。
- 数据源：AKShare（免费、MIT、覆盖 A 股 + 期货 + 基金、无需注册）+ TuShare Pro（结构化深度数据）。
- Phase 2 直接用 A 股模拟盘（而非 Steam），接实时行情做虚拟执行。
- Phase 3 只在 Phase 2 产生经过统计检验的 alpha 信号后才启动。

**适用前提**：有投资 alpha 的假说需要验证，系统是加速验证循环的工具。

**崩溃条件**：没有投资专家持续投入策略设计 → 退化成花哨的 Jupyter notebook。所有策略跑不赢指数 → 整个投资方向死亡。

---

### 方案 B：平台路线（投资只是第一个租户）

**逻辑闭环**：OpenClaw 的核心价值不是「做投资」，而是「安全地编排 agent 做复杂多步骤任务」。投资只是一个 harness。

**做法**：
- 投资系统设计成可插拔 harness 模板（skill 集合 + schema + workflow 定义）。
- 同时启动 2-3 个 harness 验证：
  1. 投资研究 harness（精简版方案 A）
  2. 代码审计 harness（LLM 的强项）
  3. 竞品监控 harness（定期抓取 + 结构化报告）
- 第一个产生商业价值的 harness 决定发展方向。

**适用前提**：对 OpenClaw 的定位是通用 agent 编排平台，投资只是其中一种可能。

**崩溃条件**：同时三件事可能都不深入。30 天内没有一个 harness 证明价值 → 注意力分散。「平台化」容易变成拖延。

---

### 方案 C：对抗性路线（Steam 市场小资金实战）

**逻辑闭环**：Paper money 无法验证真实市场表现。用 Steam 市场小资金直接实验。

**做法**：
- 跳过 Phase 1。使用第三方 API（DMarket、SteamWebAPI.com）避免 Valve ToS 风险。
- 初始资金 100-500 美元 Steam 余额，高流动性 CS2 皮肤。
- 策略极简：基于订单簿深度的均值回复，不用 LLM 做决策，用 LLM 做数据处理和异常检测。
- auditor 做实时风控：检测 pump group 信号（供给集中度上升、BUFF163 价差偏离）。
- 成功标准：30 天内完成完整循环且不崩溃。

**崩溃条件**：
- 15% 手续费 + 7 天交易锁定 → 短期策略不可行
- 中国 pump group 控制 50%+ 供给 → 信息绝对劣势
- Valve 随时改规则 → 历史数据失效
- 市场结构与金融市场完全不同 → 经验不可迁移
- 账号封禁风险

---

### 方案 D：知识生产路线（不做交易）

**逻辑闭环**：LLM 最擅长信息处理而非决策。定位为金融研究知识生产线。

**做法**：
- 构建 Equity Research Copilot：自动化卖方分析师 80% 工作（财务数据提取、行业对比、估值模型、报告初稿）。
- GUI Chat 页面作为用户界面。核心 skill 集合：financial-data-fetch → financial-model → valuation → report-generation。

**崩溃条件**：Bloomberg Terminal + GPT、AlphaSense 已经存在。需要独特数据源或工作流优势。

## 各角色视角核心洞察

### 量化投资老手

系统的价值是 operational alpha——把研究流程从「一人 Jupyter 摸索」变成「多 agent 标准化管道」。研究员一天测 2-3 个因子假说 → 系统加速到 10-15 个 → 找到有效因子的概率提升 5 倍。但永远不该让 LLM 决定仓位大小或进出场时机——需要严格数学框架（Kelly criterion、风险平价），不是自然语言推理。

最危险的幻觉：回测好 = 实盘赚钱。LLM 的 overfitting 更严重——它能在自然语言层面「合理化」任何结果。

### 系统开发者

技术瓶颈不是 agent 编排（已经很好），而是 **状态管理和持久化**。投资系统需要：portfolio 状态原子性更新、交易日志不可篡改、策略版本与回测结果严格关联。task-state.json 不够，需要时序数据库或 SQLite + WAL。

多模型决策链的责任归属：GPT-5.4（main）分配 → deepseek-chat（task-runner）回测 → opus-4-6（auditor）审查 → main 综合决策。任何环节出幻觉，debug 成本是指数级的。需要架构层面的 **decision audit trail**。

### 竞争对手

如果知道有人用 LLM agent 跑 Steam 策略，可以：
1. 观察订单簿上的规律性模式（LLM 决策有隐含一致性）
2. Front-running：在其大概率买入时刻挂高价单
3. Signal injection：通过小额交易操纵短期价格信号。Steam 市场流动性薄到这完全可行。

### 怀疑论者

最可能的失败模式是 **安静的失去兴趣**：
1. 两周搭建数据管道和回测框架
2. 跑策略，发现跑不赢沪深 300 ETF
3. 调参数，in-sample 好看但 out-of-sample 不行
4. 怀疑数据源问题，换数据源
5. 三个月后系统还能跑但没人看了

不是技术失败，是「缺乏快速反馈循环」导致的动力衰减。投资策略反馈周期天然长（数周到数月），人的注意力跟不上。

## 最值得深挖的 3 个问题

### 1. 这套 agent 编排系统的「不可替代性边界」在哪里？

一个人用 Python + Jupyter + yfinance 能在一个下午搭出基本回测框架。OpenClaw 多 agent 做同样的事，优势在哪里？如果答案是「自动化和可重复」，Airflow + dbt 也行且更成熟。如果是「LLM 灵活性」，在投资领域灵活性恰恰危险。必须找到一个场景，multi-agent LLM 编排提供的价值是其他工具栈无法复制的。

### 2. Phase 1→2→3 的跨越条件从未定义——是设计疏忽还是潜意识回避？

不知道什么条件下 paper trading「成功」，就永远不会进入下一阶段。「表现好」不是标准——多好算好？什么市场环境？持续多久？定义标准本身需要投资领域的专业判断。

### 3. 「与投资领域专家合作」——这个专家存在吗？

Phase 1 的设计基于隐含假设：有投资专家参与策略定义、信号设计、决策框架。交接文档只有技术准备清单，没提到专家是谁、何时介入、如何协作。如果就是系统开发者本人，需要明确——同时做系统开发和投资研究是截然不同的认知负担。如果不存在，现在最该做的是找人而不是搭框架。

## 自由发散区

**OpenClaw 最好的第一个客户是 OpenClaw 自己。** agent 系统管理和改进 agent 系统本身：自动检测 hotfix 是否生效、验证权限持久化、OpenClaw 升级后自动重新应用补丁。这本身就是有价值的 harness。

**Steam 市场可能是个陷阱。** 市场结构（无做空、7 天锁定、15% 费率、pump group 主导）跟金融市场差异太大。经验不可迁移。更糟：可能产生虚假自信。

**GPT-5.4「总是填充可选参数」在投资决策中的类比。** LLM 倾向于 action over inaction（训练数据中有用的回答通常是做了什么而非什么都没做）。让 LLM agent 每天出交易建议，它会每天都给建议，而正确答案可能是 80% 的日子什么都不该做。

**3D 打印机类比。** 造好精密打印机后，第一个打印品不应该是手表机芯（投资 = 对输出质量要求极端），应该是手机壳（代码审计/研究报告 = 有用、容错空间大）。

**如果 LLM 推理成本 12 个月内降 10 倍？** 可能打开暴力搜索策略空间的窗口：LLM 生成 1000 个策略变体，全部跑回测，统计方法筛选。genetic algorithm + LLM as mutation operator，比 LLM as portfolio manager 更有前途。

**Decision journal as a product.** 不做交易，做决策记录和复盘。agent 抓取持仓变化、当时市场数据、新闻环境，自动生成决策复盘报告。不触碰交易合规问题。LLM 最擅长的事——信息综合和叙事构建。

## 如果只能做一件事

**定义 Phase 1 的成功标准和退出条件，写成一页纸文档，在写任何一行代码之前。**

这个文档需要回答：
1. 策略类型（量化因子？事件驱动？技术分析？）
2. 标的范围（A 股全市场？沪深 300 成分股？）
3. 回测时间跨度和频率
4. 成功的量化门槛（跑赢基准 X%？夏普 > Y？最大回撤 < Z%？）
5. Out-of-sample 验证方法
6. 时间框：N 周/月内未达标做什么
7. 谁是投资专家，如何参与

不需要代码，不需要 agent，不需要 Docker sandbox。需要一次深度对话和明确答案。

## 附录：外部研究关键发现

### A. LLM 交易 agent 学术现状
- StockBench (ICLR 2026)：多数 LLM agent 跑不赢 buy-and-hold
- TradeTrap (Shanghai AI Lab)：小扰动可级联为灾难性损失
- AlphaAgents：多 agent debate 改善分析但不解决决策质量
- FinMem：分层记忆架构在回测中优于 FinGPT 但未经实盘验证

### B. Steam 市场结构
- 15% 总手续费（Steam 5% + 游戏 10%）、7 天交易锁定
- 中国 pump group 控制 50%+ 供给，2025 年多次 1000%+ 拉升后崩盘
- 无官方交易 API，自动化交易有 Valve 封号风险
- Frontiers in AI 论文证实 AI 在 CS2 皮肤市场可实现 15-20% ROI（2 月期）

### C. 中国量化监管
- 2024-2026 年全面收紧：CSRC 程序化交易管理规定、期货程序化交易规定
- 高频交易门槛：20+ 次/秒且 20+ 交易日
- CSRC 已要求量化基金提交程序代码审查
- AI 交易无专门禁令但受程序化交易全部规定约束
- 跨境数据传输需合规评估

### D. 数据源推荐
- AKShare：完全免费开源、MIT 协议、覆盖广、无需注册
- TuShare Pro：173 接口、积分制、结构化深度数据
- 两者已有 MCP server 可直接接入 agent
